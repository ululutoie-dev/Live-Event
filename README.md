# ライブ告知ページ

## 管理画面(ブラウザから編集)のセットアップ
1. supabase.com で新しいプロジェクトを作る
2. SQL Editor に `supabase/schema.sql` を貼る。**先に `YOUR-ADMIN-EMAIL` を自分のメールに書き換え**てから Run
3. Authentication の Users から、そのメールでユーザーを追加(パスワードを設定し、メール確認済みにする)
4. Authentication の設定で、**新規サインアップ(Allow new users to sign up)をオフ**にする
5. Project Settings の API で、Project URL と `anon` `public` キーを控える(`service_role` キーは絶対に使わない)
6. Vercel のプロジェクトの Settings → Environment Variables に次の2つを追加し、再デプロイ
   - `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`
7. `公開URL/#/admin` を開いてログイン(管理画面だけはこの形です) → 編集 → 「保存して公開」

メモ
- 公開ページの一番下の小さな「編集」リンクからも入れます
- SNSに貼ったときのプレビュー(OGP)の仕組みは、下の「リンクプレビュー」を参照してください
- Supabaseの無料プロジェクトは、長期間アクセスがないと停止することがあります

## 複数イベントの使い方
- 管理画面(`公開URL/#/admin`)の最初の画面が「イベント管理」です。全イベントが開催日の新しい順に並びます
- 「＋ 新しいイベントを作成」で新規イベントを追加(既存のイベントには触れません)。新規は「非公開」で始まります
- イベント編集の「公開設定」で、イベントごとに公開/非公開を切り替え。非公開は管理画面にだけ残ります
- 公開ページ: 公開中が2件以上なら一覧(EVENTS)、1件ならそのイベントの詳細がトップに出ます
- 各イベントの個別URL: `公開URL/e/<公開URL用ID>`(管理画面の一覧の「告知ページ」から開けます。イベントのUUIDでも開けます)
- 出演者はイベントごとに独立しています。イベントを削除する機能はありません(非公開にして残す運用です)
- 短い公開URL: 編集画面の「公開URL用ID」(半角英小文字・数字・ハイフン、2〜40文字、例 `vol8`)を設定すると `公開URL/e/vol8` で開けます。IDは他のイベントと重複できません。旧形式の `公開URL/#/e/vol8` や `公開URL/#/event/<UUID>` も、コード上は引き続き開けるようにしてあり、開くと `/e/…` に切り替わります(Vercel上での動作は未確認)
- 一覧の「QRコード」から、告知ページURLのQRコードを表示してPNG保存できます(URLは `公開URL/e/<公開URL用ID>`。ドメインは下の「公開ドメイン」を参照)
- Supabase側のSQL変更は不要です(既存のテーブル構成のまま動きます)

## リンクプレビュー(LINE・X・Facebookなど)
仕組み(コード上の設計):
- トップページ(`/`)のプレビューは `index.html` の固定内容です(タイトル「LIVE EVENT」。必要に応じて書き換えてください)
- イベントページ `/e/<公開URL用ID>` へのアクセスは、`vercel.json` の rewrite で `api/og.js` に渡されます。`api/og.js` は Supabase から**公開中**のイベントだけを読み、タイトル・日付・会場・説明の1行目・画像を `<head>` に入れた HTML を返します。ブラウザではこの HTML から通常どおり React アプリが起動します
- 画像の優先順位: メインビジュアル → 最初に写真がある出演者(並び順) → `public/ogp.jpg`。クローラーが取得できる絶対URL(`http(s)://…`)だけを使い、相対パスは公開ドメインを付けます
- 非公開・存在しないイベントでは、イベント情報は入りません(存在しない/非公開は404、取得に失敗したときは既定のタグのまま返し、キャッシュしません)
- タイトルなどの特殊文字(`& < > " '` と `$`)はエスケープして出力します
- 応答はCDNに最大約1分キャッシュされます。LINEなど外部サービス側のキャッシュは別なので、すでに貼ったURLは古い表示が残ることがあります。新しいURLを使うか、URLの末尾に `?v=2` のように付けてください

注意:
- `#` 以降はLINEなどから見えません。プレビューを正しく出すには、`#` なしの `/e/…` の形のURLを貼ってください(管理画面の「QRコード」のURLもこの形です)。旧形式のURLは、そのままではトップページと同じプレビューになります
- `npm run dev`(ローカル)では `api/og.js` は動きません。確認はVercel上で行ってください

## 公開ドメイン
- 現在の本番ドメインは `https://live-event-red.vercel.app` を前提にしています(`vite.config.js` の既定値)
- ドメインを変える/独自ドメインを使う場合は、Vercelの環境変数 `VITE_PUBLIC_URL`(例 `https://example.com`)を設定して再デプロイしてください。`index.html` の `og:url` / `og:image`、管理画面のQRコードのURL、`api/og.js` が同じ値を使います。未設定のとき `api/og.js` はアクセスされたドメインを使います

## Vercelへのデプロイ後に確認すること(未確認の項目です)
1. `/e/<公開URL用ID>` を直接開いて、通常どおり表示される(404にならない)
2. Chromeで `view-source:https://<ドメイン>/e/<公開URL用ID>` を開き、`og:title` `og:description` `og:image` `og:url` がそのイベントの内容になっている
3. `og:image` のURLをブラウザで開いて、画像が表示される
4. 非公開のイベントのURLでは、`og:title` にイベント名が出ない
5. LINEの「Keepメモ」に `https://<ドメイン>/e/<公開URL用ID>`(`#` なし)を貼って、プレビューを確認する
6. 旧形式 `https://<ドメイン>/#/e/<公開URL用ID>` を開くと、同じイベントが表示され、アドレスが `/e/…` に切り替わる
7. 管理画面(`/#/admin`)で、ログイン・保存・公開切り替え・「告知ページを開く」ボタン・QRコードが動く
8. `/e/<ID>/`(末尾にスラッシュ付き)で開けるか

## 内容を変える
- `src/data.js` : イベント情報・出演バンド・メールアドレス・色とフォント(`theme`)
- 画像は `public/` に入れて `"/flyer.jpg"` のように指定(バンド写真は `public/images/`)
- `public/ogp.jpg` : SNSに貼ったときのプレビュー画像(1200x630px)。仮画像なので差し替えてください

## Vercelで公開する
1. このフォルダをGitHubのリポジトリにアップロード
2. Vercelで「Add New → Project」からそのリポジトリを選び、そのまま Deploy(Viteは自動認識されます)
3. 公開ドメインが `live-event-red.vercel.app` 以外の場合は、環境変数 `VITE_PUBLIC_URL` を設定(上の「公開ドメイン」を参照)
4. 公開URLをFacebook・X・ホームページ・メールに貼る(Instagramはプロフィールのリンク欄かストーリーズ)

## バンド・リンク・地図
- バンドを増やす: `src/data.js` の `bands` に `{ ... }` を追加(`youtubeUrl` と `links` は省略可)
- 外部リンク: `links: [{ label: "Instagram", url: "https://..." }]` をいくつでも
- 会場の地図: 会場名と住所からGoogleマップを開きます。別の地図にしたい場合は `mapUrl` にURLを入れる

## 色・フォントを試す
公開URLの末尾に `?design` を付けると「デザイン」ボタンが出ます。決まったら `src/data.js` の `theme` に反映。

## YouTube
